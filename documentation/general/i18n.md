# UI language support (Español / English)

The dashboard renders its static interface text in Spanish (default) or English. A selector in the
top bar (and on the login page) switches between them.

## How it works

| Piece | Where |
|---|---|
| Catalogs (flat `key -> text`, same keys in both) | `src/i18n/locales/es.json`, `en.json` |
| Lookup: `t(key, **params)`, `t_or`, `vocab`, `page_title`, `LazyLabels`, `VocabMapping` | `src/i18n/__init__.py` |
| Language selector component + its clientside callback | `dashboard/components/language_selector.py` |
| Cookie handling, reload, `window.appI18n.t` for JS | `dashboard/assets/i18n_language.js` |
| Strings the browser-side JS needs (keys under `js.`) | served per request by `/_i18n/messages.js` (`dashboard/app.py`) |
| Display helpers for pipeline values | `dashboard/components/labels.py` (`status_label`, `localize_elapsed`) |

* The app is rendered on the server (layouts *and* callback outputs), so the language has to be
  known server-side. The preference is stored in the `app_language` cookie (1 year, `SameSite=Lax`),
  which the browser sends with every request; `t()` reads it from the active Flask request.
* Choosing a language writes the cookie and **reloads the page** (same URL). A reload is what makes
  the server re-render every piece of static text. The selected client is kept across the reload
  (`client-selector` is persisted per user in `sessionStorage`); view-level state such as internal
  tab selection or filter values starts from its defaults again.
* No cookie (first visit) or an invalid value means Spanish. Outside a request (tests, scripts,
  import time) `t()` also returns Spanish.
* A key missing in English falls back to Spanish; a key missing everywhere renders the key itself
  (and logs a warning once), so a gap is visible instead of blank.

## Adding or changing UI text

1. Never put user-visible text directly in a component. Use `t("namespace.key")` and add the key to
   **both** catalogs (keep the files sorted, one flat object, 1-space indent).
2. Dynamic parts become placeholders: `t("x.y", count=3)` with `"{count} units"`. Text with no params
   is returned verbatim, so literal braces (Plotly's `%{x}`) need no escaping; text *with* params goes
   through `str.format`, so write `%{{x}}` there.
3. Call `t()` when the component is built (inside a function). A module-level constant would freeze
   the language of the process at import time. For constant tables use `LazyLabels({value: key})`,
   or keep the identifier table and translate at the point of display.
4. Keep identifiers and display text apart: dropdown `value`s, DataTable column ids, dict keys and
   filter queries stay as they are; only labels/headers/cell text are translated. If a table shows a
   translated status, its `style_data_conditional` filter must use the same translated text
   (see `tables.py`, `machines_callbacks.py`, `telemetry_callbacks.py`).
5. Do not cache anything that contains translated text (`lru_cache`, module-level snapshots).
   Cache raw values and translate when rendering (see `MergedCell` in `fleet_overview.py`).
6. Text that clientside JS renders must live under the `js.` prefix and be read with
   `window.appI18n.t(key, fallback, params)`; the Spanish fallback keeps the JS usable without it.

`tests/test_i18n.py` enforces: identical key sets and placeholders in both catalogs, identical edge
whitespace, every `t("literal")` used in code exists, every formatting call supplies the placeholders
its text needs, plus the lookup/cookie/selector behaviour.

## Scope

In scope: static interface text - labels, buttons, menus, tabs, placeholders, tooltips, messages,
errors, chart titles/axes/legends/hover text, table headers, browser-tab titles.

Translated at display time, never in the data: pipeline status values (`Normal/Alerta/Anormal`,
...), elapsed-time strings, failure-mode names, oil-variable/essay names and signal descriptions
(`vocab()` - keyed by their exact Spanish text, so the shared Spanish catalogs that Campbell AI reads
stay untouched).

Out of scope (left as delivered by the backend/data): database values (unit/component/equipment
names, maintenance system names), AI-generated text (alert diagnoses, Campbell AI answers, telemetry
comments) and anything produced by the pipelines. Number and date formats are unchanged.

Known gaps: the legacy Health Index charts and tables (not reachable from the navigation) and
`dashboard/tabs/tab_overview_general_old.py` / `components/accumulated_curve.py` (no longer imported)
were not converted.
